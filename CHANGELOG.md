# Changelog

## Unreleased

- Added Blueprint, JCL, Julius, Lucius, Mako, MLIR, Ren'Py, Slang, Snakemake (which now has `Snakefile`), Tact, TTCN-3, TypeSpec, Ur/Web, and Visual Studio Solution, and about 170 extensions and filenames that tokei, scc, cloc, or loc know and codestats didn't, such as `.sbt`, `config.ru`, `Vagrantfile`, `.bashrc`, `.zshrc`, C++'s module extensions (`.ccm`, `.cxxm`, `.mxx`), GLSL and HLSL shader extensions, Interface Builder's `.storyboard` and `.xib`, `.vsixmanifest`, and `.webmanifest`. Translation files (`.xliff`) and other data are still left out
- In HTML, a `<script>` or `<style>` tag that's never closed is text in the page rather than the start of code that runs to the end of the file, and a quoted attribute value, like `title="<!-- text"`, no longer opens a comment. Quotes only open a value right after an `=`, so an apostrophe in a page's text opens nothing
- `cs -` counts the paths listed on standard input, one per line or NUL-separated, so `git ls-files -z | cs -` and `fd -e rs | cs -` work. Listed files are counted as named, listed directories are walked, and the filters of a walk apply, except `.gitignore`. On the Linux kernel, `git ls-files -z | cs -` takes 441 ms, where walking it takes 491 ms
- Breaking: the linguist attributes in `.gitattributes` files apply, as they do in GitHub's language statistics. Files marked `linguist-generated` are generated, and `-linguist-generated` keeps a file counted whatever its name or header say; `linguist-vendored` and `linguist-documentation` files are left out; and `linguist-language=Rust` sets a file's language where its name doesn't say, so a `*.bgt linguist-language=AngelScript` written for GitHub's sake still leaves BGT files as BGT. Nested files, files above the counted directory up to the repository's root, and `[attr]` macros all count. `--no-gitattributes` (or `respect_gitattributes = false`) turns them off. On zig, whose vendored libc, libc++, and compiler sources are marked, this leaves 3,000 of 19,000 files
- Breaking: files whose opening comments say they're generated, such as Go's `// Code generated by stringer; DO NOT EDIT.`, protobuf's `Generated by the protocol buffer compiler`, C#'s `<auto-generated />`, and `@generated`, are left out by default, like lockfiles and minified assets. `--include-generated` counts them. On Kubernetes that's a quarter of its lines, and it makes counting there 14% faster
- Lockfiles and minified assets are told apart by name as each file is counted, rather than by matching every path against globs, which saves about 2% of the work on a repository like Spring
- Breaking: JSON reports, including `cs diff`'s, list the counted paths in `paths` and no longer have `path`, and `schema_version` is 2
- Breaking: the `size` column in CSV and TSV is now `bytes`, as in JSON and `cs diff`'s CSV
- Breaking: an unknown key in a config file is an error naming it, rather than silently ignored, so a typo like `sort_bye` is caught
- Breaking: `--top-languages 0` (or `top_languages = 0`) is an error pointing to `--quiet`, rather than reporting that no languages were found
- A config file can set `paths = ["src", "tests"]`, relative to the file; `path = "src"` still works
- C3 vector types like `int[<*>]` no longer open a `<*` documentation comment, which turned much of C3's standard library into comments (`mem.c3` went from 40 lines of code to 555), and C3's strings, char literals, and backtick raw strings are recognized
- A D file whose only sign of being D is a `;` (rather than one of its keywords) is counted as D; Make's dependency files, which share the `.d` extension, still aren't
- C++ raw strings with a delimiter of their own, like `R"sql(...)sql"`, end only at that delimiter, so a `)"` or comment marker inside one is text
- The HTML in PHP files, outside their `<?php ... ?>` tags, is counted by HTML's rules and listed as embedded HTML, with its scripts and styles as theirs, so `<!-- -->` comments in a template are comments. PHP's strings may also span lines now, as they can in PHP
- Perl's POD documentation only starts and ends at a marker at the very start of a line, so `=head1` in a string or an indented `=cut` in the documentation is text, and MATLAB and Octave block comments (`%{`, `%}`) only count alone on their line
- PowerShell here-strings (`@'...'@`, `@"..."@`) are recognized
- A C string carried onto the next line by a backslash ends at a blank line
- `cs completions` no longer panics when its output is cut short, as by `cs completions bash | head`
- Several paths can be counted together, as in `cs src tests build.rs`. Files are listed by the path they were reached by, and a path given twice or inside another is only counted once. `cs diff` still takes one path. JSON reports list them in a new `paths` field
- The summary's list of languages ends with "and" before the last one, like the other lists in human output
- A plain heredoc (`<<EOF`) only ends at its word at the start of a line, while `<<~EOF` and `<<-EOF` (and any heredoc in PHP) may end at an indented one, and Ruby's `class <<self` is no longer taken for a heredoc
- In C, C++, Objective-C, and CUDA, a line comment ending in a backslash carries on onto the next line, as the compiler reads it
- In shells and PowerShell, a quote escaped outside a string (`don\'t`, ``don`'t``) no longer opens one
- CMake's bracket comments and arguments with equals signs (`#[==[ ... ]==]`) are recognized, and a tripled quote followed by more quotes (`""""`) ends its string at the last of them
- Strings are recognized in Nix, Julia, OCaml, Visual Basic, R, PowerShell, Protocol Buffers, and Fish, so comment markers inside them are no longer counted as comments. In Nix, a shell glob like `images/*.gif` in a script string used to start a comment that could run for thousands of lines, and in Visual Basic, an apostrophe in a string like `"Don't"` started one
- Faster at telling apart languages that share an extension, such as C, C++ and Objective-C headers: linux is counted about 8% faster. With `--lang` or `--exclude-lang`, files whose possible languages are all filtered out are skipped without being read, unless they start with a shebang
- Faster on languages whose strings or comments start with a letter, like Rust's raw strings (`r"`), and on languages with four or more kinds of comment and string markers, like Go: the rust repository is counted about 20% faster and kubernetes about 9%
- Fixed counting hanging forever on some tiny files with a zero byte, such as a JSON test case with a NUL in a string. They were mistaken for UTF-16, and decoding a UTF-16 file with an odd number of bytes could get stuck at its end. A single zero in a tiny file is no longer taken for UTF-16

## 0.9.1

- Embedded code is now broken down by language. Each language lists the languages embedded in its files and their lines, such as the JavaScript in Markdown files, in every output format: an `embedded` list on languages and files in JSON, an "Embedded code" list in human output, and an embedded code table in CSV and TSV (with `--verbose`), Markdown and HTML. Embedded lines still count toward their file's language
- Code blocks in AsciiDoc (`[source,python]` listings and fenced blocks), Org (`#+BEGIN_SRC`) and reStructuredText (`.. code-block::` and similar directives) are counted by their own language's rules, like those in Markdown
- HTML-based templates count their `<script>` and `<style>` elements by those elements' languages, as HTML files do. This covers ASP.NET, Blade, EEx, EJS, ERB, FreeMarker, Go Template, Hamlet, Handlebars, Java Server Pages, Jinja2, Liquid, Marko, Mustache, Nunjucks, Razor, Smarty, Twig, and SVG
- Heredocs are recognized in Bash, Zsh, C Shell, Perl, Ruby, Crystal, and PHP, so their bodies count as code: a `#include` or `#define` written out by `cat <<EOF`, or the assembly a Perl script generates, is no longer counted as comments. Shifts and appends like `x << y` and `class << self` aren't mistaken for heredocs
- Bash and Zsh strings, TOML's multi-line strings and CMake's quoted and bracket arguments are recognized, so a `#` inside them is no longer counted as a comment
- Device tree overlays (`.dtso`) count as Device Tree, property lists (`.plist`) as XML, and the `makefile.vc`, `makefile.gcc`, `makefile.bcc` and `makefile.unx` files wxWidgets builds with as Makefile
- More code block names are recognized, such as `shell`, `golang`, `elisp`, `csharp`, and `latex`
- Counting a single file with `--verbose` shows its name instead of an empty path
- Faster on files with many comment lines or a lot of non-ASCII text, such as translations: nvda, which is mostly translations, is counted about 15% faster

## 0.9.0

- Code embedded in another language is counted by its own language's rules, while its lines still belong to the file's language: `<script>` and `<style>` elements in HTML, Vue, Svelte, and Astro (following `lang` and `type`, so `lang="ts"` is TypeScript and `lang="scss"` SCSS), Astro's TypeScript frontmatter, and fenced code blocks and YAML or TOML frontmatter in Markdown. A `// comment` in a Svelte script or a Markdown Rust block now counts as a comment rather than code, and a stylesheet wrapped in old-style `<!-- -->` hiding counts as CSS rather than one long comment
- Xcode prefix headers (`.pch`) are counted, as C, C++, or Objective-C like `.h` files
- A file of a format that can be a program, like a BRLTTY contraction table (`.ctb`), is counted as the language of its shebang when it starts with one
- Added `cs diff <FROM> [PATH]`, which compares each language's files and code, comment and blank lines between a git revision and the working tree (or another revision with `--to`), in every output format. On the Linux kernel a diff against `HEAD` takes about 2 seconds
- Added `--git` (`git_tracked_only` in config files) to count only the files git tracks, including in submodules; hidden, excluded, and generated files are still left out, and `.gitignore` doesn't apply to tracked files
- Breaking: JSON output has a new, consistent shape with a `schema_version` (1). Line counts are a `lines` object (`total`, `code`, `comment`, `blank`, `shebang`) at every level, sizes are `bytes`, file counts are `file_count`, and per-file details are `files`. `summary` is now `totals`, `analysis_path` is `path`, a directory's `path` is its `name`, and `languages_hidden`/`dirs_hidden` are `hidden_languages`/`hidden_directories`. Percentages, averages, and `*_human` sizes are gone from JSON; the other formats still show them

## 0.8.4

- Added Texinfo (`.texi`, `.texinfo`, `.txi`), XAML (`.xaml`), and braille tables: liblouis (`.ctb`, `.cti`, `.utb`, `.uti`, `.dis`) and BRLTTY (`.ktb`, `.kti`, `.ttb`, `.tti`, `.atb`, `.ati`)
- 6502 assembly (`.s65`, `.a65`) counts as Assembly
- Dependency files that compilers write for Make (`.d`) are no longer counted as D; D files are recognized by their keywords and doc comments
- `.tmpl` and `.gotxt` files count as Go Template, `.vcproj` and `.vcxproj.filters` as MSBuild, and Autoconf's `configure.ac` and `configure.in` as M4
- C3 test files (`.c3t`) count as C3, and lowercase `sconscript`/`sconstruct` files as Python, as NVDA's build uses
- 20-40% faster than 0.8.3 (37% on the Linux kernel), with identical counts
- The README benchmarks now cover eight repositories, including nvda, wxWidgets, and rust-lang/rust, at commits pinned in `scripts/bench.sh`, which reproduces them; cloc is no longer included

## 0.8.3

- `.h` files can now be C++: a header is counted as C++ when it has C++-only constructs such as `namespace`, `template`, `std::`, `virtual`, or access specifiers, and as C otherwise. On wxWidgets, about 1,870 headers counted as C are now C++, while the Linux kernel's 27,000 headers stay C
- Keywords inside comments no longer count when the languages sharing an extension write comments the same way (C, C++, and Objective-C), so a C header discussing "virtual memory" isn't taken for C++; for the same reason, some Objective-C headers whose documentation comments use `@class` are now correctly C++
- C, C++, Objective-C, and LPC keywords now match case-sensitively, so `VIRTUAL` or `TYPEDEF` in an assembly or BASIC include file no longer counts as C++
- Faster, most of all on code with ambiguous extensions like `.c` and `.h`: about 40% faster on the Linux kernel and 17-30% faster on react, cpython, and kubernetes, making codestats the fastest of the tools in the benchmarks on every repository

## 0.8.2

- `--by-dir` now works in CSV, TSV, Markdown, and HTML output, which previously ignored it and showed the language breakdown; with `--verbose` they also list each directory's files
- Markdown tables now render: a blank line between each table's header and its rows made GitHub-flavored Markdown end the table before its first row
- `-q` with Markdown or HTML output no longer ends with "No recognized programming languages found."
- `--by-dir --sort-by files` now sorts directories by file count rather than line count
- `--min-lines` is now applied before `--top-languages`, so `-t 3` shows three entries whenever three pass the threshold, whatever the sort order
- Binary files made of small 16-bit values (lookup tables and the like) are no longer mistaken for UTF-16 text and counted as code
- Piping into a command that stops reading early, like `cs | head`, no longer prints "Error: Broken pipe" or exits with an error
- Invalid option values now name the option, list the accepted values and suggest the closest one (`-o xml` suggests `html`) instead of "one of the values isn't valid for an argument"
- Files of a language left out by `--lang` or `--exclude-lang` are skipped without being read when their name alone identifies the language

## 0.8.1

- JavaScript and TypeScript regex literals are now recognized, so a regex containing a backtick or `/*` (as in jQuery Validation) no longer turns the following lines into code or comments
- Shebangs using `env -S` (`#!/usr/bin/env -S deno run`) are recognized, and shebangs now match whole interpreter names, so `node` no longer claims `nodemon` and `perl6` is Raku rather than Perl
- Added shebangs for deno, tsx, ts-node, bun, Rscript, pwsh, swift, kotlin, osascript, sbcl, dash, make, and raku
- Improved detection for extensions shared by several languages: a keyword repeated many times no longer outweighs several distinct ones (C files that mention "mapping" are no longer LPC), and files where the decision is close are checked against more of their content
- `.inc` files are now also considered as C++, PHP, Makefile, or NASM assembly, and are only claimed by a language with real evidence, so C++ includes are no longer counted as Pascal or BitBake and unrelated `.inc` files are left out
- Preprocessor directives written with a space in assembly (`# define`, `# if defined(X)`) are counted as code rather than comments
- HTML and Markdown output are always included; the `html`, `markdown`, and `all-formats` features have been removed

## 0.8.0

- Comment markers inside string literals are now ignored, so code like `"src/**/*.rs"` or `printf("/*")` no longer turns the following lines into comments. Supported for C, C++, C#, Objective-C, Java, Kotlin, Swift, Go, Rust, JavaScript, TypeScript, Python, Ruby, PHP, Elixir, Lua, SQL, Haskell, Dart, Scala, Groovy, Zig, Nim, CSS, SCSS, Less, JSONC, JSON5, and Tcl
- Python docstrings are counted as comments, while other triple-quoted strings (`x = """...`) are counted as code
- A block comment start inside a line comment (`// see "/healthz/*"`) no longer opens a block comment, and block comments now only close with their own delimiter
- Fixed comment syntax for about 80 languages, including OpenCL `//`, ABAP `"`, uppercase `REM` in Batch, TLA+, Teal, Smarty, and template comments in ERB, EJS, and JSP, and corrected which languages' block comments nest
- Improved detection for extensions shared by several languages: `.m` and `.h` files are no longer misdetected as Octave or Limbo, SPARK is told apart from Ada and Yacc from Bison, and `.editorconfig` and `.gitconfig` are no longer INI
- Files with nothing distinctive no longer go uncounted when their extension is shared (bare `.h` and `.c` files fall back to C), and the most specific pattern now wins (`pom.xml` is Maven, `*.blade.php` is Blade)
- Exact filenames are now matched case-sensitively, so Bazel's `BUILD` no longer claims `build` scripts
- C++ now owns `.hh` (previously Hack), Perl `.t` test files are recognized, and config files like `.babelrc` and `Pipfile` count as their real formats
- Fortran is split into free-form Fortran (`.f90` and later) and Fortran (Fixed Form) (`.f`, `.for`, `.f77`), where `C`, `c` and `*` comments only count in the first column
- Added Blade, GAP, Gnuplot, Go Template, Godot Resource, HTTP, Pawn, Smali, systemd, and Yuck, plus missing extensions and filenames such as `Containerfile`, `Jenkinsfile`, `.emacs` and `meson.options`
- Removed CSV, Jupyter Notebook, MessagePack, max, Piet, and Whitespace, whose line counts weren't meaningful; XML Schema files now count as XML
- `-q` now ends with a compact list of languages and their file counts
- Startup is about 7x faster and per-file language detection is faster, making codestats 1.5-2x faster than tokei and scc on medium-sized repositories
- codestats is now a binary-only crate; the `codestats` library target is no longer published

## 0.7.0

- Added `--by-dir` (`-D`) to show a breakdown by directory instead of by language; combining it with `--verbose` also lists individual files under each directory
- Added `--max-depth N` to cap directory traversal depth
- Added `--min-lines N` to hide entries with fewer than N total lines from the breakdown
- Added `--top-languages N` to limit the breakdown to the top N entries; the output notes how many were omitted when entries are hidden by either flag
- Expanded language coverage, now covering 544 total programming languages.
- File paths in verbose and directory output are now shown relative to the analysis root instead of absolute
- Fixed unsupported block comment definitions for MoonScript
- Generated files such as lockfiles and minified assets are now excluded by default; pass `--include-generated` to count them
- Pre-built binaries are now published to GitHub Releases for Linux (x86_64/ARM64), macOS (Intel/Apple Silicon), and Windows (x86_64/ARM64)
- Renamed `--sort-dir` to `--sort-direction`; dropped the `-i` shorthand from `--no-gitignore` and `-S` from `--symlinks`
- Verbosity is now controlled with `-q`/`--quiet` (summary only) and `-v`/`--verbose` (per-file details); the default shows the language breakdown without file details
